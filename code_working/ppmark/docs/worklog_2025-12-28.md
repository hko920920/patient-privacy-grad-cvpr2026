# Work Log (2025-12-28)

## Summary
- Set up batch wrappers and evaluation logic for Muller and Zhao attacks.
- Implemented a proof-backed positive dataset builder and aligned eval metrics with HardPass definition.

## Changes
- Added `scripts/build_pos_dataset.py` to generate proof-backed WM images and manifests.
  - Supports `--secret-hex`, `--secret-file`, or `--secret-env` (default `PPMARK_SECRET_HEX`).
  - Writes `image_relpath` and `metadata_relpath` for root override evaluation.
- Updated `scripts/build_pos_dataset.py` to respect `--start-index` in output naming to avoid collisions during multi-GPU splits.
- Added Muller batch wrapper `scripts/run_muller_attacks.py`.
  - Runs reprompt/removal/forgery in batch.
  - Selects max step from `metrics.csv` and copies outputs to `outputs/attacks/muller/<attack>/<split>/images/<relpath>`.
  - Writes per-attack manifests and a summary JSON.
- Added Zhao batch wrapper `scripts/run_zhao_attacks.py` (DiffWMAttacker only).
  - Strength mapping: weak=30, med=60, strong=100 noise steps.
  - Outputs to `outputs/attacks/zhao/<strength>/<split>/images/<relpath>` and writes manifests.
- Updated `scripts/eval_attack_manifest.py` to compute:
  - `HardPass = proof_ok` (commitment validity)
  - `AcceptPass = proof_ok AND score_pass` (image validity)
  - Adds `rs_ok`, `payload_match`, `decoded_match`, and `accept_pass` to `scores.csv` (decode fields are diagnostic).
  - Adds `rs_success_rate`, `payload_match_rate`, `decoded_match_rate`, and `accept_pass_rate` to summary JSON.

## Notes
- Hard reporting should use `HardPass = proof_ok` (commitment validity only).
- Image validity should use score thresholding (`AcceptPass = proof_ok && score_pass`), with payload hash/decoded fields as diagnostic.
- Inversion-root recomputation is diagnostic only (not a gate).
- For Zhao/Muller, proof is only required for original WM images; attack images do not need new proofs.
