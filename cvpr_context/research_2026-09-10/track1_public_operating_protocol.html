공개 의료 기반모델: 한 번의 운용 조건 진단

판정: 제한된 후속 진단은 합리적이다. 새 결과는 실행 후 별도 보고한다. 앞선 공개 LoRA pilot의 확인 미통과는 그대로 닫는다. 이번은 새 공통 latent로 prompt·CFG·checkpoint의 효과를 나누어 보는 개발 실험이며, 이전 확인의 재실행이나 모델 채택 절차가 아니다. 큰 단계2·방향1을 유지한다.

1. 사용자의 검토에서 채택한 것과 제한한 것

  • 현재 recipe는 사전 운영 기준 미달이다. 16장 결과를 모델의 본질적 불안정성에 관한 모집단 확증으로 확대하지 않는다.
  • 공개자료만으로 gross CXR 형태를 형성한 사실과, 새 입력에서 기반모델 채택 기준에 못 미친 사실을 함께 유지한다.
  • 같은 initial latent를 모든 prompt와 CFG·checkpoint에 적용한다. 이전의 prompt별 다른 seed 배정은 이번에 반복하지 않는다.
  • 특정 prompt나 CFG 변경이 같은 입력의 결과를 바꾸면 해당 요인의 영향에 관한 근거가 된다. 유일한 실패 원인이나 모든 환자/seed의 일반적 원인으로 확정하지 않는다. latent 효과 역시 모델–latent 상호작용이다.
  • 추가 투자 한도는 이번 운용 진단 한 번과, 필요할 때 근거를 확인한 더 강한 공개 기반모델 한 후보다. 이번 후보가 실패하면 step/seed/CFG 값을 계속 추가하지 않는다.
  • 두 경로 모두 별도 확인을 통과하지 못하면 현재 생성 기반 방향1의 확대를 종료한다. 이는 프로젝트 자원 배분 결정이며 patient-DP의 보편적 불가능성 증명이 아니다. 다른 연구 방향의 선택은 별도 결정이다.

2. 고정 연산과 입력

요인 값
checkpoint 기존 공개 E4, E8; 새 학습 0
CFG 1, 7.5 두 값만
prompt 기존 generic, normal, effusion, cardiomegaly 네 문자열
initial latent 새 CPU FP32 seed 4개; 모든 prompt·CFG·checkpoint가 같은 실제 텐서를 공유
생성 경로 FP32, autocast 없음, 고정 SD2.1/VAE, DDIM30 eta0, 256×256
조건 embedding 이전 공개 캐시의 네 conditional embedding 그대로; 빈 문자열 embedding 한 개를 같은 고정 text encoder로 새 계산
branch 순서 CFG7.5에서 empty/unconditional 다음 conditional
이미지 수 2×2×4×4 = 64장
UNet 호출/처리 examples 1,920 calls / 2,880 examples; CFG7.5는 호출당 두 branch
역전파/새 head/DP 전부 0

seed는 실행 전 고정 salt public-operating-diagnostic-20260916-v1과 phase/index를 SHA256으로 매핑한다. 앞선 공개 pilot의 선택·확인 seed와 겹치지 않는지 검사한다. 개발 seed4개와 후속 확인용 seed4개를 같은 계약에 미리 기록하되, 이번에는 개발64장만 생성한다. 기존 확인16장의 이미지/seed를 재사용하지 않는다.

네 prompt는 같은 네 latent를 공유한다. 따라서 16개 prompt–latent cell은 독립 표본16개가 아니라 네 seed block으로 묶인다. 작은 paired 진단으로 해석하고 binomial16개나 모집단 유의성을 주장하지 않는다.

3. 구현과 수치 확인

기존 검증된 manual UNet→CFG→DDIM 경로를 재사용한다. 새 학습·sampling 알고리즘은 만들지 않는다. FP32 LoRA는 half round-trip 없이 그대로 로드하고, 전후 base/adapter 불변을 확인한다. 실제 initial/embedding, 매 step raw branch prediction·guided prediction·latent, decode/PNG를 모두 저장한다.

실행 코드·검산 코드·이 문서와 실제 checkpoint/cache/이전 실패 결정을 hash로 묶는다. 검산은 저장 tensor에 대한 별도 CFG/DDIM/PNG 산술을 이용한다. 전체 모델 재추론이나 임상 판독의 대체로 부르지 않는다.

각 동일 checkpoint·prompt·seed에서 첫 step의 conditional prediction은 CFG1의 batch1과 CFG7.5의 batch2에서 비교한다. batch 연산의 FP32 차이를 위해 고정 허용오차 atol=1e-4, rtol=1e-4를 쓰며, 이를 넘으면 구현 진단으로 중단한다. 이후 step은 CFG가 trajectory를 바꾸므로 같은 conditional prediction일 필요가 없다.

4. 판독과 결정

모델/CFG/prompt/seed가 표시되지 않은 64개 ID와 고정 순서 그림을 먼저 판독한다. 이번 개발 screen은 root 한 명의 비임상 형태 판독이다. 두 명이 판독한 앞선 pilot 통과율과 동일한 평가자 조건인 것처럼 직접 우월성을 주장하지 않는다. 모호한 사례는 미통과로 기록하며 전체 결과를 보존한다.

기준은 정면 흉부 형태와 큰 비의료 패턴·회전·중첩·구조 왜곡의 부재다. 질환 정확성·임상 효용·diversity·memorization을 판정하지 않는다. 원래 기준인 전체12/16 및 각 prompt2/4를 후속 확인 후보를 고르는 개발 지표로 유지한다.

  • CFG1은 이전 실패 조건의 새 입력 대조군이다. 이번 개발에서 좋게 나와도 이전 E4/CFG1의 미통과를 취소하거나 그대로 채택하지 않는다.
  • 변경된 운용 후보는 E4/CFG7.5, E8/CFG7.5 두 개다. 둘 다 개발 지표를 충족하면 학습이 짧은 E4를 먼저 지명한다. 어떤 cell도 결과 이후 추가하지 않는다.
  • 지명은 채택이 아니다. 미리 별도로 잡은 새 seed4개×prompt4개의 확인과 독립 판독 명세를 고정한 뒤에야 채택할 수 있다. 이번 실행은 그 확인16장을 생성하지 않는다.
  • 두 CFG7.5 후보가 개발 기준에 미달하면 이 public749/attention-rank8/SD2.1 recipe의 추가 탐색을 종료한다. 다음 후보는 사용·자료 경계를 먼저 확인한 강한 공개 의료 생성기 한 개로 제한한다.
  • 한 seed에서 모든 prompt가 실패하거나 특정 prompt/CFG에서만 실패하는 패턴은 기제의 단서로 기록한다. 네 seed만으로 원인을 확정하지 않는다.

5. 이후 작은 head를 붙일 때의 정의

학습하지 않은 null branch에 기존 conditional head를 적용하지 않는다. 후속 설계가 이 운용을 택한다면 다음처럼 conditional branch에만 적용한다.

[ \epsilon_{guided}=\epsilon_u+s\big[(\epsilon_c+\Delta_{head})-\epsilon_u\big] =\epsilon_u+s(\epsilon_c-\epsilon_u)+s\Delta_{head}. ]

Delta=0은 표준 CFG이고 s=1은 conditional prediction+head다. guidance는 head 신호뿐 아니라 그 추정 오차·DP noise의 출력 영향도 s배 키운다. 공개된 고정 s를 이미 DP인 파라미터의 추론에 사용하는 것은 후처리지만, 그것이 효용 보존을 뜻하지는 않는다. 사적 자료로 s를 선택한다면 그 선택 과정도 별도 privacy 검토 대상이다.

따라서 변경된 backbone·운용 설정에 맞는 새 특징/통계/W와 같은 CFG의 강한 기준선을 사용해야 한다. 현재 generic-base W를 가져오거나 이번 진단으로 private utility/DP 우위를 주장하지 않는다. 이번 실행에는 실제 head가 없다.

6. 시간과 범위

기록·코드 대조와 명세 작성20–40분, 새64장 GPU 생성3–6분 예상이다. 코드 연결·저장 산술 검산·64장 판독·정리를 포함한 이번 실제 패키지는 총35–60분 예상이다. 기존 약2.2초/CFG1 이미지와 두 branch 비용을 참고한 추정이며 새 측정값과 구별한다. 새 학습은 없다.

외부 공개 모델의 선정·다운로드·추가 훈련은 이번64장에 포함하지 않는다. 필요한 경우 한 후보의 provenance·호환성·예상 전체 비용을 먼저 고정하고 별도 한 번의 시도로 기록한다. 원격 main SHA 064bc653399d1b8ecbba81df846a84b7b8bae3ab은 사용자가 확인했다고 제공한 정보이며 이번 로컬 작업에서 재확인한 값으로 쓰지 않는다.
