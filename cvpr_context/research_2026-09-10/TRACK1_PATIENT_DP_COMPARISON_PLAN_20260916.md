# 방향1 다음 비교: 같은 환자 보호 수준에서 통계 보호가 유리한가

**2026-09-16 후속 실행 완료:** [공개 보정·64개 DP 모델·독립 검산 결과](TRACK1_PATIENT_DP_RESULTS_20260916.md). 아래 미실행·잠정 표시는 비교 전 설계 당시 상태이며 실제 선택은T2000이다.

2026-09-16. [첫 실제 결과](TRACK1_CAPACITY_RESULTS_20260916.md)는 작은 보정층의 비DP 적응 능력을 확인했다. **다음 질문은 이 이득이 환자 단위 DP 아래에서도 유지되고, 같은 보정층을 DP-SGD로 학습하는 것보다 품질·비용 면에서 유리한가**다. 지금은 비교 구조와 자료·회계 경로를 검토한 상태다. DP 학습 결과가 나온 것은 아니며, 공개 보정자료 추출과 최종 실행 계약이 남아 있다.

## 1. 이번 비교가 논문 주장과 어떻게 연결되나

고정 특징의 이차손실은 환자별 A/B 통계에 학습에 필요한 정보를 담을 수 있다. 통계를 한 번 보호하면 이후 해를 구하는 과정에는 추가 사적 접근이 필요 없다. 반면 DP-SGD는 매 반복의 환자 gradient를 보호하고 회계한다. 이것이 후보의 계산·보호 구조상 차이다.

그러나 통계 보호는 대칭 Gram까지 잡음을 넣는다. full64는 2,336좌표, static16은 200좌표를 보호한다. 실제 첫 결과에서 static16이 전체 MSE 감소의86.15%를 얻었고, full64의 추가 상대 감소는0.4467%다. 따라서 **한 번 보호한다는 장점과 통계 차원·역행렬 안정성의 대가를 함께 비교**해야 한다. 반복 횟수가 적다는 사실만으로 더 좋은 효용을 보장하지 않는다.

이 비교는 새 기여의 필요조건을 살펴보는 첫 단계다. One-shot 통계 보호, 사적 회귀, 고정 특징 기반 denoising은 [직접 선행 검토](TWO_TRACK_OPERATION_REDESIGN_20260916.md)에 이미 존재한다. 네 실험 칸에서 이겨도 해당 아이디어 자체를 최초라고 주장할 수 없다. 실제 생성 품질과 강한 사적 회귀·DP-LoRA 비교는 이 근거 뒤에 연결한다.

## 2. 최소 비교 네 칸과 같은 입력

| 표현 | 환자 통계에 일회 Gaussian 보호 | 같은 보정층의 환자 DP-SGD |
|---|---|---|
| 시간 독립 공간16차원 | static16-SSP | static16-SGD |
| 시간·공간64차원 | full64-SSP | full64-SGD |

- 기반 모델, 특징 projection, 환자80명·각4장, 영상당8개 시점/잡음, 환자 동일 가중치와 λ=.001은 첫 계약과 같다.
- 환자가 다른 개발평가40명에서 환자별 MSE를 측정한다. 기존 calibration/test 각140명은 계속 보존한다. 평가40명으로 clip·학습률·ridge를 골라 가장 좋은 결과만 보고하지 않는다.
- 각 환자의 고정 목적은 `L_u(W)=Q_u-2<W,B_u>+<W,A_uW>`다. 실제 gradient는 정확히 `2(A_uW-B_u)`이므로 양쪽 모두 저장된 A/B를 내부적으로 사용할 수 있다.
- 같은 head의 DP-SGD에 매번 UNet을 재실행하게 만들어 속도 이득을 부풀리지 않는다. 두 방법의 공통 특징 추출시간과 그 뒤 보호·최적화 시간을 나누어, 합산 비용도 보고한다.
- 이 동등성은 이번 고정 finite 목적에 대한 것이다. 매번 새로운 이미지·noise를 뽑는 모든 diffusion 학습과 동등하다는 뜻이 아니다.
- 비DP 해와 잡음 없는 clipping 대조도 함께 둬서 표현의 한계, clipping 손실, DP 잡음 손실, 최적화 부족을 구분한다. SSP와 SGD의 clipping은 같은 연산이 아니므로 보정 전 목적이 같다는 것과 clipping 후 목적이 같다는 것을 혼동하지 않는다.

## 3. 환자 DP 계약과 구현 조건

**선택한 비교 기준:** 한 환자의 자료 전체를 추가/제거하는 인접성, 공개 고정 분모 N0=80, 목표 ε=8·δ=1e-5. ε/δ는 이번 성능을 보고 고른 값이 아니라 기존 프로젝트의 환자 보호 기준이다. Replacement 인접성이라면 민감도가 달라지므로 같은 회계를 그대로 쓰지 않는다.

**통계 보호:** 환자별 `z_u=(svec(A_u)/a0, vec(B_u)/b0)`를 하나의 벡터로 만들고 L2 norm C에 joint clipping한다. svec의 비대각은 sqrt(2) 가중치를 사용한다. 고정 분모로 합산하고 표준편차 `sigma*C/N0`의 등방 Gaussian 잡음을 더한다. 추가/제거 민감도는 `C/N0`다. Q는 학습에 필요 없으므로 보호 출력에 넣지 않는다. a0/b0/C는 별도 공개 자료에서 정하고 고정한다.

Gaussian 결과를 A/B로 복원한 뒤 대칭화·PSD 보정·ridge 해를 계산하는 것은 고정 규칙의 후처리다. 다만 PSD/ridge 규칙은 효용을 바꾸므로 사적 성능을 보고 무료로 조정하면 안 된다. 현재 helper는 준비되어 있지만 **최종 PSD 규칙과 보정값은 아직 실행 계약으로 동결하지 않았다.**

**DP-SGD:** 매 step 환자별 Poisson sampling, 환자 gradient clipping, gradient 합에 표준편차 sigma*C의 Gaussian noise, 공개 고정 분모 `q*N0`로 나눔을 사용한다. 공개 ridge gradient `2*lambda*W`는 환자 clipping과 잡음 뒤에 한 번 더한다. 빈 batch에서도 noise-only update와 회계 event를 수행하며 건너뛰지 않는다.

q=.1·T=500은 최초 검토 예산(기대 batch8명·기대50회 순회)이다. **공개 자료에서 최적화 충분성을 확인하기 전 최종 SGD 예산으로 확정하지 않는다.** 비DP 동일 optimizer가 공개 이차목적의 해에 충분히 접근해야 하며, 잘못된 학습률·부족한 반복으로 baseline을 약화시키지 않는다. SSP와 SGD의 C는 단위가 다르므로 같은 숫자로 맞추는 것이 공정성은 아니다. 같은 독립 공개 자료와 사전에 정한 선택 절차를 준다.

**회계:** 기존 [이중 회계 구현](../../code_working/dp_protocol/build_xray_dp_attack_protocol.py)의 Opacus RDP와 Google dp-accounting RDP를 대조한다. SSP는 q=1·T=1, SGD는 실제 확정 q/T의 event를 사용한다. ε=8에서 소규모 ε 조건의 간단한 Gaussian 근사식만으로 보장을 선언하지 않는다. 이번 회계 점검은 공개 상수 계산이며 DP 모델 학습이 아니다. 서로 같은 ε/δ 상한도 실제 공격 위험이 동일하다는 뜻은 아니다.

회계만 먼저 실행해 [원자료와 경고 기록](spec_sources/track1_dp_accounting_precheck_20260916.json)을 남겼다. 총12.123초의 CPU 계산이며 새 모델은 학습하지 않았다.

| 공개 회계 조건 | 잡음 배율 σ | Opacus ε | Google ε |
|---|---:|---:|---:|
| SSP q=1, T=1 | 0.6376701852 | 8.0 | 8.0 |
| SGD 잠정 q=.1, T=500 | 1.6360149290 | 7.9954374702 | 8.0 |

두 구현의 큰 ε를 기준으로 보수적으로 맞췄다. 초기 σ 탐색에서 낮은 fractional order의 수렴 경고가 있었고 해당 order는 무한대 상계로 제외됐다. 최종 최적 order3.9/3.7에는 해당 경고가 없었다. SGD의 최종 q/T가 바뀌면 다시 회계한다. **σ만으로 두 방식의 실제 잡음 크기나 효용 우열을 비교할 수 없다.** clip 단위·통계 차원·정규화·반복 합성이 다르기 때문이다.

## 5. 실행 전에 남은 구체적 작업과 판정

독립 명세 검토에서 현재 목적·민감도·샘플링·공개 보정·비용 비교에 진행을 막는 오류는 발견되지 않았다. 이는 DP 실행 검증이 아니다. 최종 구현에서는 W0를0 또는 공개 자료만으로 정한 값으로 두며, 기존 비DP 사적 해로 초기화하지 않는다. 고정 환자별 사진 선택·특징·noise는 다른 환자의 추가/제거에 따라 바뀌지 않도록 한다.

1. 공개32명의 통계를 별도 폴더에 추출·검산한다. 기존 비DP 원자료와 결과는 그대로 보존한다.
2. 공개 자료만으로 a0/b0, 각 방식의 C, PSD 규칙, SGD 학습률·반복 수를 결정하는 절차를 문서와 코드에 고정한다. 공개 비DP 최적화 대조를 통과한 후 네 칸을 실행한다.
3. 실제 q/T의 회계를 확인하고 noise 반복 수·seed·집계 방식·비용 측정 구간까지 결과 전에 고정한다. 같은 보호 수준에서 각 표현·보호방식의 MSE 분포와 비용을 보고한다.
4. 강한 단순 대안도 개선을 유지하면 그대로 인정한다. full64 추가 이득이 잡음에 사라졌다면 원인을 분석하고, 평가 결과에 맞춰 몰래 C나 seed를 다시 고르지 않는다. SSP가 더 낫다는 결론은 같은 표현의 정상적인 DP-SGD 비교 이후에만 내린다.

**성공의 의미:** 비DP에서 관찰한 적응 이득이 환자 DP 아래 남고, 단순 표현과 반복 학습 대비 유의미한 품질–비용 선택지가 생긴다. 이 경우 실제 생성 품질 및 가까운 사적 회귀 비교로 이어갈 근거가 된다. 현재는 그 결과를 보장하지 않는다.

**보호 보장의 범위:** 최종 고정 메커니즘의 선택된 모델 출력에 대한 계약이다. 원시 환자 통계·비DP 해·환자별 손실·공개한 재현 seed까지 담긴 연구 폴더 전체가 DP라는 주장은 하지 않는다. 이전 비DP 결과의 공개를 나중의 DP로 소급해 보호할 수 없다. 여러 모델·seed·사적 선택 결과를 함께 공개한다면 그 출력과 선택의 합성 비용을 별도로 회계해야 한다.

예상 작업시간은 공개 보정과 비교 구현·회계·독립 검토 **30–60분**이다. 이는 사람/코드 작업 포함 예상이며, DP 계산 자체의 실측 시간이 아니다. 새 대규모 backbone 학습은 필요 없고, CPU 실행은 작은 profile 후 총시간을 보고한다.
