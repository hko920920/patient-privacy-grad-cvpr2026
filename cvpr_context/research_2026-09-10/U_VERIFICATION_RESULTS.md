# U 파일럿 실제 재검증 결과

후속 최신 판정: [기존 SecMI 방법의 E/U 48명 진단](U_BASELINE_SCREEN.md). 아래는 그 전에 완료한 기존 8명의 수치 재검증 기록이다.

2026-09-14. 사용자 요청에 따라 기존 자료·학습 기록을 재검증하고, 빠진 수치 검사를 실제 GPU에서 실행했다. 기존 8명과 두 모델을 사용했다. **기존 파일럿의 재현·계측·수치 검산과 FP32 endpoint 보완을 완료했다. 후보의 판별 성능이 입증된 것은 아니다.**

가장 중요한 발견은 미세한 참여 모델−미참여 모델 점수 차이가 평가 정밀도에 민감하다는 점이다. 기존 8명 전체를 동일한 FP32 endpoint 조건으로 다시 계산했으며, 후보 R의 AUC는 모델 1/2 각각 **0.6875/0.2500**, 양의 paired 차이는 **3/8명**이었다. 분할·미분·최적화의 동작을 확인했지만 일관된 후보 효과는 확인하지 못했다.

## 1. 검증 범위와 수정

- 기존 분할·노출·checkpoint·품질 파일·E/U 점수·AUC 계산을 다시 확인했다. 선택 영상 2,304장의 hash와 핵심 테스트 4개를 재검사했다.
- 기존 probe가 버리던 support 목적값을 저장하도록 별도 계측 코드를 만들었다. 6단계의 계수·gradient·update·projection, 마지막 목적값, query/reference의 개별 loss를 기록한다.
- 비영점 입력 gradient를 유한차분 및 checkpointing 켬/끔과 대조했다. FP16 차분의 정밀도 영향을 같은 입력의 FP32 계산으로 분리했다.
- 최초 수치 실행은 비교 요약만 저장했으므로, 원시 gradient 벡터도 보존하는 v2를 추가 실행했다. v1과 v2 측정값은 시간·메모리를 제외하고 정확히 재현됐다.
- E 대조를 기존 1명 실행에서 기존 U 환자 8명 전체의 E/U 기본 점수 비교로 보완했다. 일반 prompt와 학습 때 사용한 weak-label prompt를 따로 평가했다.
- 기존 코드·checkpoint·원점수를 보존했다. 계산 규칙을 바꿔 성능을 높인 수정은 아니다. 확인된 수정 대상은 **계측 누락, 검증 누락, 과도한 원인 해석과 낡은 현황 표기**다.

## 2. 실제 입력 미분과 최적화

첫 U 실행의 첫 환자·첫 support 영상·model 1을 실행 순서로 선택했다. 결과가 좋은 입력을 고른 것이 아니다. t=500의 고정 noise에서 방향 미분을 비교하고, FP32에서는 8개 계수 좌표도 모두 검사했다.

| 확인 | 실측 |
|---|---|
| 기존 코드와 새 FP16 계측의 loss·gradient | 정확히 동일 |
| checkpointing 켬/끔 | FP16·FP32 각각 loss·gradient 정확히 동일 |
| 같은 조건 반복 | loss 차이 0 |
| FP32 방향 차분, h=0.001 | AD 대비 상대 오차 0.0360% |
| FP32 방향 차분, h=0.0002 | 상대 오차 0.0743% |
| FP32 전체 8좌표 차분 벡터 | 상대 L2 오차 0.0372% / 0.2275%, 좌표 부호 불일치 0 |
| FP16 방향 차분, h=0.005 / 0.001 / 0.0002 | 상대 오차 0.228% / 2.279% / 43.058% |
| 6단계 support 목적값의 최종 증가 | FP16 +0.00945013 / FP32 +0.00913045 |
| FP16·FP32 초기 3-timestep gradient 차이 | 상대 L2 0.559% |
| FP16·FP32 최종 계수 차이 | 상대 L2 2.383% |

FP16의 아주 작은 차분 간격에서는 계산이 불안정했다. 이를 자동미분 버그로 판정하지 않는다. 같은 noisy latent와 target을 승격한 FP32 차분이 자동미분과 잘 맞고 실제 최적화 목적값도 증가했다. 모든 좌표의 상대 오차가 0.1% 미만이라는 뜻은 아니다. 작은 좌표에서는 최대 4.57%였으며 위 표의 전체 벡터 오차와 구분한다.

**이 결과는 검사한 한 입력의 국소 미분과 최적화에 대한 근거다.** 모든 입력·noise·최종 환자 점수의 정밀도 강건성이나 membership 검출력을 증명하지 않는다. FP32는 원래 FP16 모델·입력 값을 승격한 대조이며 별도로 복원한 원본 FP32 pretrained model이 아니다.

수치 verifier는 저장된 셀 집계, 12회 update/projection, 22개 차분과 원시 gradient 비교, source/checkpoint hash를 독립 CPU 코드로 재계산했다. GPU weight 불변은 실행기의 parameter version·gradient 및 adapter tensor 동일성 검사에 근거한다.

## 3. 기존 8명 전체 재현

**8명×2모델의 16회 재현을 완료했다.** 원래 6개 점수, 총 96개 값이 정확히 같았다. 32개 support 과정 모두 최종 목적값이 증가했다. 최소 증가는 +0.00423631, 최대는 +0.01191018이었다.

192회 update 중 한 번의 중간 감소도 숨기지 않는다. model 2·환자 12511의 다섯 번째 update에서 목적값이 0.0000943023 감소했지만 그 과정의 최종 증가는 +0.00787182였다. 해당 update에는 projection이 적용되지 않았다. 원래 고정 step 규칙은 매 단계 증가를 보장하는 line search가 아니므로 이를 곧바로 구현 버그로 부르거나 사후에 좋은 경로만 선택하지 않는다.

독립 verifier가 loss 셀·계수 update·참조·정답·hash와 5,184F/1,152B를 재계산했다. 실행기의 실측 경과 시간은 **824.17초(13분 44초)**, 환자 한 명·모델 한 개당 중앙값은 **51.15초**였다. 모델 로딩·결과 저장을 포함하며 외부 코드 준비와 독립 검증은 제외한다. 추가된 마지막 support 목적값 평가로 원래 312F/72B에서 324F/72B가 됐다.

## 4. E/U 기본 점수 비교

1,280개 paired loss 셀, 128개 영상 점수, 64개 조건별 환자 점수와 모델별 AUC 24개를 독립 재계산했다. 아래는 고정된 양의 membership 방향의 기본 점수 진단이다. **이 표는 FP16 batch 4 실행이며, 뒤의 FP32 U 재평가와 구분한다.**

| 조건 | 음의 평균 loss AUC: 모델 1 / 2 | base−target 평균 AUC: 모델 1 / 2 |
|---|---|---|
| E, generic | 0.5625 / 0.5625 | 0.2500 / 0.8125 |
| E, matched weak-label | 0.5625 / 0.5625 | 0.2500 / 0.6875 |
| U, generic | 0.7500 / 0.2500 | 0.6250 / 0.4375 |
| U, matched weak-label | 0.7500 / 0.2500 | 0.6250 / 0.4375 |

이 작은 진단에서는 prompt를 맞춘 것만으로 판별이 뚜렷이 좋아지지 않았고, E에서도 일관된 강한 양성 대조를 확보하지 못했다. E의 음의 평균 loss 점수가 같은 환자의 참여 모델에서 높아지는 경우가 두 prompt 모두 6/8명이었다. 즉 실제 평균 loss는 그 경우에 낮아졌다. 이것은 분석자가 두 모델을 비교한 기술 통계이며 일반 감사자가 얻는 입력이나 독립적인 인과 검정이 아니다.

기존 U batch 1과 비교하면 영상 평균 loss의 최대 절대 차이는 target 5.615×10⁻⁶, base 5.735×10⁻⁵, base−target 5.774×10⁻⁵였다. 세 기본 점수 모두 참여/미참여 환자쌍 순서와 paired delta 부호는 유지됐다. 따라서 현재 U 원점수 해석을 위해 배치를 다시 돌릴 근거는 없었지만, 수치가 정확히 같은 것으로 표기하지 않는다. endpoint 정밀도 대조는 별도로 수행했다.

[E/U 기본 대조](../../code_working/_reports/cvpr_u_pilot_v1_001/verification_20260914/basic_controls/analysis.json) · [독립 검증](../../code_working/_reports/cvpr_u_pilot_v1_001/verification_20260914/basic_controls/verification.json)

E는 train_candidate 사진을 관측하며, 참여 모델에서는 그 관측 사진이 학습에 포함되고 비참여 모델에서는 제외된다. U는 그 환자의 다른 사진이 학습됐더라도 감사자가 보는 사진 자체는 미사용인 조건이다. 두 모델의 실제 노출에서 정답을 확인했다.

matched weak-label은 추가 정보를 주는 별도 조건이다. 이를 원래 generic 감사자의 성능으로 합치지 않는다. 모델당 참여 4명·미참여 4명의 개발 진단이므로, 작은 AUC 차이를 신뢰할 만한 판별력이나 낮은 FPR 성능으로 주장하지 않는다.

## 5. 최종 점수의 평가 정밀도

동일 첫 환자의 저장된 FP16 계수를 고정하고 두 모델에서 FP32로 query/reference 점수만 다시 계산한다. 입력·계수·noise·참조는 고정하고 평가 정밀도만 바꾸는 대조다. 최적화 경로 변경과 평가 수치 효과를 분리한다.

**이 검사에서 첫 환자의 작은 paired 차이 부호가 실제로 뒤집혔다.**

| 값 | 원 FP16 endpoint | 계수 고정 FP32 endpoint |
|---|---:|---:|
| model 1의 R | −0.001834219455 | −0.001818591601 |
| model 2의 R | −0.001848497521 | −0.001791671093 |
| 참여 모델−미참여 모델 차이 | +0.000014278066 | −0.000026920508 |

개별 R의 부호가 바뀐 것은 아니다. **작은 참여 관련 차이의 부호가 평가 정밀도에 안정적이지 않았다.** 원 코드의 MSE는 이미 FP32, 최종 scalar 차감은 Python float였다. 따라서 “FP16 마지막 뺄셈 버그”라고 하면 틀리다. 이번 변경은 UNet 내부 연산과 conditioning 입력 cast를 함께 FP32로 바꾼 것이다.

이 결과에 따라 전체 8명 결과를 보기 전에 [정밀도 평가 규칙](../../code_working/_reports/cvpr_u_pilot_v1_001/verification_20260914/endpoint_precision_policy.json)을 고정했다. 기존 8명 전원과 두 모델에서 R·음의 평균/최대 loss·base−target 점수에 동일한 FP32 endpoint를 적용한다. 기존 계수는 그대로 두며 유리한 환자나 항만 정밀도를 바꾸지 않는다. 원 FP16 결과와 재평가 결과를 함께 보존한다.

**전체 8명×2모델의 FP32 endpoint 재평가와 독립 검증을 완료했다.** FP32/원 FP16 각각 1,920개 paired loss 셀, 32개 fold, 64개 환자 점수와 양쪽 정밀도 AUC 16개를 재계산했다. 첫 환자의 별도 FP32 실행도 240개 raw 셀이 정확히 재현됐다.

| 점수 | 원 FP16 AUC: 모델 1 / 2 | FP32 endpoint AUC: 모델 1 / 2 | 양의 paired 차이: 원본 → 재평가 |
|---|---|---|---|
| 후보 R | 0.6875 / 0.3125 | **0.6875 / 0.2500** | **4/8 → 3/8** |
| 음의 평균 loss | 0.7500 / 0.2500 | 0.7500 / 0.2500 | 5/8 → 5/8 |
| 음의 loss 최댓값 | 0.6875 / 0.3125 | 0.6875 / 0.3125 | 4/8 → 4/8 |
| base−target 평균 | 0.6250 / 0.4375 | 0.6250 / 0.4375 | 5/8 → 5/8 |

여기서 최대 loss 점수는 두 영상의 **음의 loss 중 최댓값**이다. 후보 R은 model 2에서 환자 한 쌍의 순서가 바뀌고, 한 환자의 paired 차이 부호가 바뀌었다. 나머지 세 기본 점수의 AUC·환자 순위·paired 부호는 유지됐다. 표의 3/8은 정확도나 TPR이 아니다.

정밀도 보완 후에도 현재 고정 양의 R 단독 후보를 뒷받침하는 일관된 결과는 없었다. 이 재평가는 개발 진단이며, 전체 FP32 재최적화·새 noise 반복·새 환자/seed·학습된 점수 결합의 결과는 아니다. 전체 방법의 불가능성이나 특정 보정항의 결함으로 확대 해석하지 않는다.

## 6. 해석과 다음 판단의 경계

기존 양의 R 단독 AUC는 모델 1/2 각각 0.6875/0.3125였다. 원래 설계에 있던 개발 fitting, 기존 특징 대비 R 추가 이득, 별도 선택·보정·시험은 아직 실행하지 않았다. 이번 검증이 그 성능 실험을 대신하지 않는다.

- 보정 후 분산 증가를 보정항 결함으로 판정한 설명은 철회한다.
- 같은 순위와 뒤집힌 정답에서 생기는 평균 AUC 0.5를 여러 독립 실패 증거로 세지 않는다.
- E에서도 뚜렷한 단서가 없다는 작은 진단만으로 학습 부족, 신호 부재, 공격 한계 중 원인을 확정하지 않는다.
- 원래의 교차 사진 반응 R이 정확한 선형 관계 대조보다 나은지는 아직 비교하지 않았다. 기존 gradient dot/cos는 동일 query/reference 조건의 정확한 1차 근사가 아니다.
- 한 쌍의 공동 배정 교환 모델은 독립 seed 반복이나 단일 환자만 다른 DP 인접 실험이 아니다.
- 현재 8명으로 연구 가능성·불가능성 또는 CVPR 기여를 확정하지 않는다. 16명·80명은 이전에 충분한 검정력에서 계산된 규모가 아니었다.

**검증 통과와 성능 성공을 분리한다.** 후속 연구 판단에는 정보·비용·환자 단위 보정을 맞춘 강한 비교, 개발 자료에서 정한 방법의 별도 평가, 보호·효용 비교가 필요하다. 추가 환자 확대나 장시간 재학습이 이번 수치 검사로 자동 정당화되지는 않는다.

## 7. 예상 시간과 실측 시간

각 단계 시작 전에 예상 시간을 보고했다. 아래 초 단위 실측은 실행기 내부의 경과 시간이며 모델 로딩·내부 결과 저장을 포함한다. 외부 코드 준비·독립 검증·문서 작성은 별도다. 순수 GPU 커널 시간이나 앞으로의 전체 연구 시간으로 해석하지 않는다.

| 단계 | 시작 전 예상 | 실측 |
|---|---|---|
| 분할·학습·기존 점수 재검사 | 5–10분 | 준비·검토 포함 약 5분 |
| 수치 계측 구현·실행·검토 | 10–20분 | v1 두 정밀도 측정 합계 약 41.75초; 준비·검토 별도 |
| E/U 기본 점수 실행·검증 | 5–10분 | 79.56초; 독립 검증 별도 |
| 원시 gradient 기록 보완 재실행 | 1–2분 | v2 두 정밀도 측정 합계 약 38.41초 |
| 기존 U8 전체 추적 재현 | 10–15분 | 824.17초, 독립 검증 통과 |
| 계수 고정 FP32 최종 점수 대조 | 추가 2–4분 | 49.38초, paired 부호 민감성 발견 |
| 민감성 발견 후 U8 전체 FP32 endpoint 보완 | 최초 추가 10–12분; 준비 지연과 잔여 시간 갱신 보고 | 실행기 350.98초(5분 51초); 구현·검토·독립 검산까지 약 15분 |

이번 재검증 작업은 18:16경 시작해 19:09경 최종 증거 집계까지 약 53분이 들었다. 문서·HTML 마무리 검사는 그 이후다. 새 정밀도 민감성을 발견해 마지막 전원 재평가가 추가됐고, 그 범위와 예상 시간을 실행 전에 보고했다. 모든 검증 단계의 source/report/hash를 최종 집계에서 확인했으며, 보호 대상으로 잡은 원본 11개는 그대로였다.

이후에도 **작업 전에 범위·예상 시간, 도중에 실측에 따른 남은 시간, 종료 후 실제 시간과 판정**을 보고한다.
