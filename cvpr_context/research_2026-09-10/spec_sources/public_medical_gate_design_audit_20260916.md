# 공개 의료 backbone 계획: 독립 방법론 점검

2026-09-16. 새 학습·GPU 추론·품질 점수 계산은 하지 않았다. 현재 제안과 기존 실제 기록을 읽고, 다음 한 번의 공개 backbone pilot이 답할 질문과 한계를 정리했다. 본 메모는 실행 계약을 대신하거나 새 합격선을 추가하지 않는다.

## 권고 결론

**공개 역할 자료로 한 번의 새 LoRA trajectory를 학습하고, 사전 고정한 E4/E8 두 checkpoint 중 가장 이른 형태 확인 통과본을 택해 새 생성 입력으로 한 번 확인하는 현재 제안은 타당하다.** 목적은 작은 사적 head의 효용을 증명하는 것이 아니라, 다음 비교에 쓸 의료 도메인 backbone을 비용 제한 안에서 확보할 수 있는지 판단하는 것이다. 노출 checkpoint {1,2,4,8} 전체를 추가할 필요는 없다.

기존 generic-base+head는 고정 두 입력의 기본 형태 진단에서 실패했고, 기존 의료 M1은 같은 sampling 경로에서 흉부 형태를 보였다. 이는 공개 의료 적응을 시도할 근거이지만, 그 M1의 의료 품질·새 공개 자료 학습의 성공·작은 head의 충분한 표현력을 보장하지 않는다. [기존 LoRA 대조 결과](../TRACK1_LORA_POSITIVE_CONTROL_RESULTS_20260916.md)

## 현재 계획에 맞춘 최소 명세

| 항목 | 고정할 내용과 허용되는 해석 |
|---|---|
| 자료 | 자료 담당자의 현재 후보는 보수적으로 역할을 분리한 905명/1,016장 안의 train640·selection128·confirmation128·reserve9 환자다. 실제 이미지 수·분할·기왕 사용 여부는 새 manifest/감사로 확정한다. 이 메모에서 명부를 다시 집계하지는 않았다. private80·dev40·잠긴 calibration/test와 public32 및 기존 별도 참조 집합은 이번 backbone 선택에 쓰지 않는다. |
| 초기화 | pinned generic SD2.1 원 artifact에서 새 rank8 LoRA를 시작한다. 기존 비DP M1 adapter에서 이어 학습하지 않는다. M1은 재현된 진단 대조로만 남긴다. |
| 학습량 | 한 trajectory의 E4/E8만 보유·검사한다. E의 뜻을 전체 고정 학습 영상 명부를 네/여덟 번 순회한 횟수로 명시하고, image presentation 수·optimizer update 수·환자별 실제 노출 분포를 저장한다. 샘플러·배치·마지막 배치 처리를 계약에 적는다. |
| 선택 입력 | 기존 normal/effusion 두 prompt-seed 입력은 연결 진단에 재사용하되 선택 점수에서 제외한다. 선택은 사전에 지정한 4 prompt×4 새 seed의 전체16장으로만 한다. prompt가 같고 seed가 새로우면 새로운 생성 입력이지 새로운 임상 조건 검증은 아니다. |
| 형태 판정 | 각 영상에 frontal CXR-like 여부와 심한 회전·중첩·비의료 패턴 여부를 기록한다. 모호함 및 두 검토자 불일치는 실패로 처리한다. 체크포인트 표시를 가린 고정 임의 순서로 개별 판정 후 집계하며, 원16장을 모두 보존한다. |
| 운영 기준 | 전체12/16 이상이고 각 prompt2/4 이상이라는 제안을 유지할 수 있다. 둘 다 통과하면 E4를 선택한다. 75%는 결과 전 고정한 heuristic pilot 운영 기준이며 임상 타당성·통계적 신뢰수준·논문 효용의 합격선이 아니다. |
| 확인 | 선택된 checkpoint만 사전 지정한 별도 4 prompt×4 새 seed의16장으로 동일 판정한다. confirmation 결과를 보고 E8로 바꾸거나 seed·CFG·prompt·기준을 바꿔 같은 confirmation을 다시 쓰지 않는다. 실패하면 이 bounded recipe의 확인 실패를 기록하고 해당 pilot을 닫는다. 공개 의료 적응 전체가 불가능하다는 결론은 아니다. |
| 결과가 바꿀 결정 | 통과하면 공개 의료 backbone 위에서 public-only와 private-increment를 비교할 다음 실행의 명세를 만들 수 있다. 이 단계 자체는 사적 추가 가치나 patient-DP 방법 성공을 판단하지 않는다. 실패하면 새 private head·DP solver 탐색을 자동 실행하지 않는다. |

두 에이전트의 눈으로 판정했다면 그 사실을 그대로 기록한다. 이를 두 명의 독립 의료 전문가 판독이나 검증된 임상 평가기로 부르지 않는다. 고정 분류는 재량을 줄이지만 검토자의 오류·공통 편향을 제거하지 않는다. 현재 단계에서는 판정 기준이나 후보를 더 늘리는 것보다 위 한 패키지의 범위를 지키는 편이 낫다.

**실제 평가 단위 주의:** selection128/confirmation128 환자 명부를 예약해도, 그 환자 영상으로 손실·특징분포·조건 정합을 평가하지 않고 생성16장만 검토하면 환자 holdout 평가를 수행한 것이 아니다. 이때 결과는 새 prompt-seed 입력에 대한 생성 확인이다. 예약 환자 명부와 실제로 소비한 평가 자료를 실행 보고서에서 구분해야 한다. 기존 KID/BioViL 도구를 추가할 때도 별도 시행 없이 이미 실행한 것으로 적지 않는다.

## 노출과 비교에서 피할 혼동

1. E4/E8은 서로 같은 trajectory의 학습량 checkpoint다. 기존 M1과 평균 image exposure가 같아도 환자·영상 다양성, prompt 분포, gradient 수, 배치 구성 및 최적화 상태가 다르므로 동등한 학습량·생성 품질이라고 할 수 없다. E=4라는 명칭만으로 공정한 품질 비교가 완성되지 않는다.
2. 영상 수가 환자마다 다르면 image-uniform 공개 학습은 환자균등 목적과 다르다. 둘 다 공개 backbone 학습 방식으로 선택할 수 있지만 기존 샘플러를 환자균등이라고 잘못 기술하지 않는다. 이후 patient-DP head의 환자균등 통계와도 구분한다.
3. 가장 이른 통과본을 선택하는 규칙은 큰 checkpoint를 선호하는 결과 후 선택을 줄인다. 그러나 선택16장의 통과율을 독립 confirmation 결과처럼 합쳐32장의 정확도로 보고하지 않는다.
4. 현재16장에는 기존 KID subset50 계약을 그대로 적용할 수 없다. KID/PRDC를 계산할 수 있다는 것과 이 작은 표본으로 안정적인 순위·의료 효용을 판단할 수 있다는 것은 별개다. 이미 고정된 형태 pilot에 이를 새 의무 gate로 추가하지 않는다. [평가기 준비·참조 분리 감사](generation_evaluator_readiness_20260916.md)

## 공개 역할과 개인정보 보장의 경계

NIH 공개 데이터의 연구용 역할 분할은 실제 의료기관의 비공개 자료 보호와 동일한 데이터 접근 환경이 아니다. 공개 학습에 사용한 환자에게 새 DP 보장을 제공한다고 하지 않는다. 이번 공개 backbone의 자료 출처와 환자 교집합을 명시해야 한다.

공개 자료와 backbone 선택 과정이 보호 대상 private 환자들에 의존하지 않고 고정되어 있으며, 그 고정 backbone을 조건으로 후속 private 기구가 환자 인접성에 대해 DP라면 그 범위의 보장을 주장할 수 있다. public backbone의 과거 학습까지 소급해서 보호하는 뜻은 아니다. 향후 실제 민감 자료 적용에서는 환자 전체 자료를 제거하는 인접성과 공개 side information의 범위를 분명히 해야 한다.

기존 비DP M1에는 현재 private80 중40명·dev40 중20명이 포함된다. M1 위에 DP head를 붙이거나 M1을 공개 자료로 추가 학습한다고 해서 기존 비DP 노출이 지워지지 않는다. 현재 계획에서 M1을 public backbone으로 재분류하지 않는 것이 중요하다. [원 학습 출처 감사](lora_positive_control_provenance_20260916.md)

## 통과 이후 공정한 public-only / private-increment 비교

새 공개 의료 backbone을 먼저 고정하고, 동일한 공개 자료·feature 정의·sampling 조건에서 다음을 구분한다.

- 공개 의료 backbone 자체, 보정 W=0.
- 같은 backbone 위에서 공개 자료만 이용해 적합한 head.
- 동일 backbone·표현에서 공개+private 자료를 이용한 비DP head: 사적 추가 효용의 참고 비교다. 유한 ridge 학습목적의 해가 held-out 생성 효용의 상한이라는 뜻은 아니다.
- 위에서 실제 추가 가치가 남는 경우의 환자DP head 및 같은 head를 학습하는 공정한 patient-DP-SGD. 공개 정보 활용 범위와 공개/사적 목적함수를 맞춘다.

선택된 backbone이나 공개 초기화에 필요한 비용을 전체 비용에서 빼지 않는다. 공통으로 재사용하는 학습비와 새로운 private 적응의 한계 비용을 각각 보고할 수 있다. 후속 보호 비교에서 사용하는 private80/dev40은 그때의 별도 실행 명세에만 열며, 이번 공개 backbone의 checkpoint 선택으로 거슬러 사용하지 않는다. 작은 head의 solver 자체 신규성이 없어도 의미 있는 의료 적응·보호·비용의 통합 기여를 자동 배제하지 않는다. [현실적인 연구 계획](../REALISTIC_RESEARCH_PLAN_20260916.md)

**P 재생성은 필수가 아니다.** 기존 P는 모델 출력·사적 통계로 선택하지 않은 공개 고정320×15 random projection이다. 같은 conv_out 입력320채널을 사용하면 P와 같은 scheduler의 시간 basis를 그대로 재사용할 수 있다. 의료 backbone이 바뀌므로 실제 h0/features와 A/B/Q 및 학습 W는 새로 계산해야 한다. P를 다시 뽑아 좋은 결과를 고르는 추가 탐색은 하지 않는다. 층 위치·채널 수가 바뀌면 그때는 별도 feature 정의 변경으로 기록한다.

이번 점검에서 새 학습량·환자 수·합격선을 실험으로 검증하지는 않았다. root가 정한 bounded 계획을 적용하기 위한 범위 점검이며, 명부와 실행 계약의 최종 동결·실측은 아직 별도 작업이다.
