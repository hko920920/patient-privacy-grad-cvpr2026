# 방향 1 v0 계산 배분: 사전 고정 합성 검토 결과

2026-09-16. 원문 근거로 제안한 규칙의 첫 계산 필터다. 의료 모델·환자 데이터·DP 학습 실험이 아니다.

**결론: 현재의 두 번 pilot + Jacobian/guard v0는 좋은 고정 반복보다 대체로 나빴다.** 추가 계산을 배분할 수 있는 이론적 기회는 일부 남았지만, 이 규칙이 그 기회를 비용 후 이익으로 바꾼다는 증거는 얻지 못했다. 조건·κ·C를 결과에 맞춰 수정하지 않았다.

## 1. 무엇을 고정하고 실행했는가

[protocol.json](protocol.json)을 결과 계산 전에 저장했다. 고정한 것은 7개 분포 가족, master seed 20260916, C=1, κ=1, pilot 2개, 최종 반복 R∈{1,2,4,8,16}, 총비용 예산 4/8/16이다. 분포는 inside/boundary/outside, 이질성 유무, 이산/가우시안, radial/tangential, 상관 .9, 2/32/128차원을 포함한다.

각 타입에 독립 calibration 8,192회, test 16,384회를 사용했다. family별 λ와 고정 반복 혼합은 calibration에서만 정했다. 이는 해당 synthetic population을 잘 대표하는 공개 calibration이 있다는 유리한 가정이다. 다른 분포로의 전달 성능을 측정하지 않았다.

- fixed: R=1/2/4/8/16 전체를 보고하며 pilot 비용은 0.
- raw: 두 pilot의 원래 gradient variance로 배분.
- geometry: 동일 두 pilot에 v0 Jacobian과 guard를 적용.
- matched fixed: 각 adaptive의 calibration 기대비용에 맞춰, calibration clipped-MSE가 가장 작은 고정 R 또는 두 R의 공개 무작위 혼합을 선택.
- oracle: 알려진 synthetic 타입별 유한-R clipped-MSE 곡선을 calibration에서 읽어 배분. pilot 비용을 0 또는 2로 부과한 버전을 구분. 실행 가능한 private controller 성과로 세지 않는다.

최종 draws는 pilot과 독립이며 비교 방법 사이에서 같은 final draw bank를 사용했다. 비용은 한 gradient draw=1로 센다. pilot 2회까지 포함한 기대비용이다. 정확히 고정된 private batch별 비용이나 실제 GPU walltime 비교가 아니다.

실행은 [run_cpu_allocation.py](run_cpu_allocation.py)로 한 번 수행했다. CPU 본 계산 8.041420초, 7가족×23규칙=161행, paired 비교 42행이다. [전체 CSV](results.csv), [paired 차이와 모든 MC 구간](paired_comparisons.csv), [전체 JSON](results.json)을 보존했다.

## 2. 예산 8에서의 결과

MSE는 실제 clipped estimate와 알려진 clip(μ)의 squared-error 평균이다. 비율은 geometry / calibration-selected matched fixed로, 1보다 작아야 geometry에 유리하다. test에서 실제 사용 비용은 calibration 기대비용과 조금 달라 그 값도 표시한다.

| F3 inside, 서로 다른 분산 | 8.009 | 0.01617094 | 약 0.01626741 | 0.994 | 0.994 |

| F7 128차원 큰 MC 잡음, 동질 | 7.948 | 0.47842691 | 0.36607521 | 1.307 | 1.307 |

F1은 이산 proxy와 R cap 때문에 예산 8을 다 쓰지 못한다. fixed 비교도 calibration에서 관측한 그 작은 비용에 맞추었다. 명목 예산 8인 fixed R8만 비교해서 불리하게 만든 것이 아니다. paired CSV에 test 비용 차이를 별도로 기록했다. 위 표의 geometry-minus-fixed 비용 차이는 각각 +.034, +.015, +.009, +.018, −.003, +.065, −.052다.

전체 21개 geometry 조건 중 F3/B8의 약 0.6% 작은 이득을 제외하면 matched fixed보다 MSE가 컸다. F3의 그 결과는 raw와 geometry가 같은 draw마다 정확히 같은 R를 골라 같은 MSE를 낸 경우다. 따라서 geometry 고유의 성과로 해석하지 않는다. 구간은 simulation Monte Carlo 오차를 나타내며 의료/환자 성능 CI가 아니다. 여러 조건을 본 사후 선택의 유의성 주장도 하지 않는다.

## 3. 무엇이 실제로 막혔는가

### 3.1 이산 설명용 예제: 두 pilot의 분산0 판단이 중요한 타입도 놓친다

F1의 radial 타입은 어떤 평균에서도 clipped output=(1,0)이라 오차가 정확히 0이다. tangential 타입에는 반복의 이익이 존재한다. 그런데 tangential pilot 2개의 부호가 같으면 sample variance는 0이다.

test에서 geometry는 tangential 타입의 49.756%에 R1, 50.244%에 R16을 주었다. radial에는 항상 R1이다. 큰 평균 R를 쓰더라도 중요한 타입 절반이 R1에 남아 오류가 유지된다. 이 문제는 새 gradient bank로 평균 방향을 한 번 확인하는 것만으로 해결되지 않는다. 작은 pilot의 퇴화를 controller가 어떻게 다룰지가 필요하다.

같은 F1에서 pilot 2의 비용을 부과한 oracle B8은 MSE 0.000125819, fixed R8은 0.000155211이었다. 약 19% 낮은 값이다. oracle은 타입을 알고 radial R1, tangential R8/R16 혼합을 택한다. 실제 비용은 7.983이었다.

따라서 **배분 기회가 전혀 없다**는 결론과 **현재 v0가 그 기회를 찾지 못한다**는 결론은 다르다. 그러나 oracle에는 실용 pilot의 불확실성이 없으므로 이 결과를 제안 방법의 이익으로 세면 안 된다.

### 3.2 Gaussian outside: pilot의 국소 안전 판정은 독립 final draw의 경계 통과를 막지 못한다

F2 radial 타입은 μ=(2,0,…), radial standard deviation=.5다. 평균점의 Jacobian으로는 radial a=0이다. 하지만 Gaussian에는 유한-R 평균이 clipping 경계 안으로 들어올 확률이 남는다.

독립 닫힌 형태 계산으로 얻은 radial clipped-MSE는 다음과 같다.

| R | 정확한 Gaussian radial clipped-MSE |
|---:|---:|
| 1 | 0.0014421813538 |
| 2 | 0.0000478527576 |
| 4 | 0.0000001931380 |
| 8 | 0.0000000000131 |
| 16 | 약 2.82e−19 |

B8 geometry는 이 타입의 89.703%를 R1로 보냈다. 기록된 R 빈도와 위 정확한 risk를 곱하면 radial MSE=0.001293691105이고, 관측값은 0.001294920102였다. 따라서 큰 오류가 생긴 이유는 일반적인 데이터 집계 버그보다 **Jacobian이 유한 표집의 tail/boundary risk를 놓친 것**과 일치한다.

이때 tangential 오차 자체는 fixed R8보다 작아졌다. 그러나 radial 쪽 증가가 이를 압도했다. 단순히 “방향 추정을 조금 잘하면 된다”는 설명도 충분하지 않다. 독립 final law를 유지하면서 유한-R 위험을 추정하거나 보수적으로 보호하는 연결이 필요하다.

### 3.3 경계·상관·고차원에서도 pilot proxy가 기대만큼 구분하지 못했다

- F4/B8 guard 비율은 radial 약60.8%, tangent100%였다. geometry/fixed=2.651로 raw의1.904보다도 나빴다. Guard가 있다는 사실이 유한-R error bound라는 뜻은 아니다.
- F6/B8은 raw보다 geometry가 나았으나 여전히 fixed의2.132배 MSE였다. calibration에서 true delta-method a와 proxy의 상관은 raw .0072, geometry .0410으로 작았다. 같은 총분산의 다른 방향 구조를 2개의 noisy pilot으로 충분히 구분하지 못했다.
- F7의 guard 비율은 두 타입 모두100%여서 geometry=raw였다. 큰 MC noise가 작은 오차 Jacobian 동기를 뒷받침하지 않는 조건이다. 여기의 noise-dominant는 MC gradient noise를 뜻하며 추가 DP Gaussian noise를 넣은 실험은 아니다.
- F5는 true a가 동일하므로 proxy–a 상관이 원칙상 정의되지 않는다. 초기 코드의 부동소수점 표준편차가 0 대신 극소수로 나와 약1e−16의 상관값을 저장했다. 원본을 수정하지 않고 [arithmetic_audit.json](arithmetic_audit.json)에 이 값을 해석하지 않는다고 명시했다.

## 4. pilot 비용을 이길 최소 수학 조건

국소 error 모델을 a_u/r_u로 놓고, user당 총예산 B 중 pilot에 p를 사용한다고 하자. cap, 최소 R, 정수화, proxy 추정오차가 없는 이상적인 연속 oracle의 오차는

    oracle = (E sqrt(a))² / (B−p)
    fixed  = E a / B
    ratio  = [B/(B−p)] / [1+CV(sqrt(a))²].

따라서 **이 이상적인 a/r 모형 안에서** fixed보다 좋아지려면

    CV(sqrt(a))² > p/(B−p)

가 필요하다. p=2이면 B=4에서 CV>1, B=8에서 CV>0.577이다. 균일한 a에서는 이길 수 없다. 절반의 a가0인 이상적인 두 타입은 CV=1이므로 B4에서는 oracle조차 경계이고, 실용 제약을 넣으면 더 불리해진다.

이 조건은 실제 clipped-MSE 전체에 대한 보편적인 필요조건이 아니다. Gaussian tail이나 clipping 경계의 비선형 항을 a/r가 표현하지 못하면 F2처럼 예측이 어긋난다. 또한 oracle 조건을 만족해도 pilot 오판·R cap·minimum·integer cost 때문에 v0는 실패할 수 있다.

## 5. 목적함수·산술·비용 검산 범위

각 test final draw는 pilot과 독립이고 원래 μ를 갖는다. 그래서 모든 pilot P에 대해

    E[ μhat_{R(P)} | P ] = μ

가 정확히 성립한다. 배분이 바뀌어도 preclip target은 바뀌지 않는다. clipping 후 unbiasedness는 주장하지 않는다. 저장한 coordinate mean/SE는 유한 MC 확인이고, 정확한 등식의 증명 대신 p-value 판정을 사용하지 않았다.

독립 [audit_saved_arithmetic.py](audit_saved_arithmetic.py)는 실행 모듈을 import하거나 본 MC를 다시 돌리지 않고 다음을 검산했다.

- protocol/script/output hash 및 CSV 161/42행 확인.
- R 빈도에서 pilot 포함 비용161개 재구성: 최대오차0.
- 타입별 MSE에서 전체 MSE 재구성: 최대오차2.22e−16.
- F1 고정 R의 정확한 binomial 기대오차 계산. 유한 MC의 최대 차이는 약2.94 SE였으며, 이를 수치 오류로 강제 해석하지 않았다.
- F2 radial Gaussian 기대오차와 observed R 빈도에 따른 기대오차 계산.
- 동질 a의 상관 계수가 정의되지 않는 표시.

검산 CPU 시간은 .031004초다. 이것은 저장 산술/특수분포 기대값 검산이며, 별도 neural gradient 검증이나 모든 MC 경로의 독립 재실행은 아니다.

## 6. 이번 결과가 다음 설계에 주는 의미

현재 v0를 그대로 실제 의료 gradient 128회에 옮겨 효율성이 나올 것이라고 기대할 근거는 부족하다. 이번에 드러난 설계 연결은 구체적이다.

1. 두 pilot의 분산0/방향 추정 오판을 비용이 적은 방법으로 어떻게 다룰 것인가.
2. pilot 평균의 국소 Jacobian 대신 **fresh final 평균의 유한-R clipping 위험**, 특히 경계 통과를 어떻게 반영할 것인가.
3. 그 보수성이 만드는 minimum repeat 비용까지 포함해 좋은 고정 R를 이길 수 있는가.

이는 추가 κ/C sweep을 자동으로 하자는 제안이 아니다. 이번 protocol·코드·결과는 고정한다. 위 문제를 해결하는 다른 연산이 논리적으로 제안된다면 별도 설계와 사전 조건으로 검토해야 한다. 새로운 규칙을 만들기 위해 모든 보호 baseline을 먼저 실패시켜야 한다는 뜻도 아니다.

현재 완료물은 **방향1의 첫 구현 규칙이 어디에서 막히는지 드러낸 CPU 필터**다. 같은 환자 DP 보장, 실제 모델 품질, AdamW 효과, GPU 시간 절약, 새 논문 기여는 이번 결과로 입증하지 않았다.
