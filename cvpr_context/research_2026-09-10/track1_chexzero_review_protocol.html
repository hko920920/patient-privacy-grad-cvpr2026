방향1: CheXzero 단일 대안 검토와 다음 검증 고정

2026-09-17, 큰 단계2·방향1, 예상20–30분. 이번 작업은 문헌/공식 구현/자산/별도 개발자료를 확인하는 단계다. 새 NIH pixel·모델 추론·생성·DP는 하지 않는다. 직전 PadChest 실패를 유지한다. CheXzero까지 검증에 실패하면 현재 두 질환 공동 가설에서 classifier 탐색을 종료한다.

1. 검토할 평가기 하나

공식 rajpurkarlab/CheXzero commit 5c341db0fe0db2f663a2c136c7120a8b303f1d11와 README가 가리키는 공개 checkpoint10개 전부의 ensemble이다. 이는10개 방법 중 최고를 고르는 실험이 아니다. 파일 집합을 먼저 저장하고 같은10개를 equal-weight 평균한다. Local NIH 성능에 따라 subset/checkpoint/template을 선택하지 않는다. Source는 MIT이고 LICENSE/NOTICE를 함께 보존한다. 공개 weight 배포 사실과 재배포/상업적 이용 허가를 자동으로 같은 것으로 해석하지 않는다.

Source zero_shot.py/공식 notebook의 template ("{}", "no {}")를 사용한다. Primary query는 Emphysema, Pneumothorax, 즉 네 문자열 Emphysema, no Emphysema, Pneumothorax, no Pneumothorax다. 같은 target의 normalized positive/negative text/image cosine으로 각 checkpoint에서 softmax하고 그 후10개 값을 평균한다. 공식 코드대로 temperature1, CLIP의 학습 logit_scale 미적용. Disease 간 softmax, raw positive cosine 단독, 동의어/긴 문장 탐색은 하지 않는다. Text 질의 가능성과 실제 target 구별력은 별개다.

2. 학습 경계와 근거 확인

논문의 MIMIC-CXR medical adaptation, CheXpert validation 모델 선택, 외부 PadChest/CheXpert 평가를 구분한다. CLIP 초기화의 원 웹학습 corpus는 완전한 환자 수준 배제증명이 아니므로 ‘NIH를 절대 본 적 없음’은 주장하지 않는다. 공개 의학 적응/선택 단계에 NIH가 포함됐다는 기록이 있는지 공식 source를 확인한다. 두 target의 외부 AUC는 해당 disease 이름으로 source data를 직접 확인하고 subcutaneous emphysema 등 다른 소견과 혼동하지 않는다.

3. 새 evaluator-only 자료의 고정 규칙

기존 PadChest evaluator80명은 소비된 개발자료다. 이번 대안의 정식 판정에는 쓰지 않는다. Input은 그80명을 이미 제외한 padchest_validation_20260917_v1/remaining_development_private.csv4,133명이다. 원래 reserved confirmation4,213명과 모든 잠긴 final/test는 보존한다.

상호배타적 primary군은 직전과 동일: 보유 PA 환자 label 합집합에서 E+/P−, P+/E−, 두 target 없는 Effusion, 세 질환 없는 환자의 No Finding 영상. 다른 질환 동반은 허용한다. 신규 salt cvpr-chexzero-evaluator-20260917-v1로 SHA256(salt+'|patient|'+정수ID) 오름차순 첫20명/군, 총80명을 다음 검증용으로 예약한다. 각 환자의 해당 label 영상 중 SHA256(salt+'|image|'+imageID) 최솟값1장. Metadata 선택만 하며 이번엔 pixel/모델 결과를 열지 않는다. 명부를 기록하고 score 이후 환자/이미지를 교체하지 않는다.

새80명을 예약하면 development4,053명이 남고 E-only는64→44명, P-only197→177명, No Finding2,152→2,132명, Effusion774→754명이다. 따라서 이전의 생성 reference64명/군 예시는 유지할 수 없다. 후속 개발 reference는32명/군을 계획값으로 내려 양쪽 split에서 가능하게 한다. 이는 아직 method 결과를 보지 않은 자원 배정 수정이며 검정력 보장이 아니다. 생성 분포 평가가 더 큰 reference를 요구하면 범위를 낮추거나 외부 자료를 확보해야 하고 final/confirmation을 개발용으로 당겨쓰지 않는다. Reserved confirmation의 소규모 reference 명부 자체는 이번에 선택하지 않는다.

4. 다음 실제 검증의 계산 조건

공식 data_process.preprocess→zero_shot.make 경로를 따른다. PNG8bit grayscale, PIL LANCZOS로 종횡비 유지320/검은색 padding, gray3채널 복제, intensity0–255에서 mean101.48761/std83.43944 normalization, bicubic224. 설치 torchvision 최신 default로 조용히 바뀌지 않도록 legacy tensor Resize의 antialias=False를 명시한다. Removed Image.ANTIALIAS는 같은 LANCZOS enum으로만 치환한다. 전처리와 label binding을 독립 검산한다. 환자가 모두1024square라는 이유로 다른 normalization을 적용하지 않는다.

현재 환경을 old requirements로 downgrade하지 않는다. 가중치는 안전한 tensor-only 로딩으로 구조/전체 key/shape/finiteness를 확인한다. 실제 검증에서는 공식 CLIP architecture에 checkpoint 전체를 strict-load하고 CPU FP32 reference와 GPU FP32 경로를 고정입력으로 대조한다. 초기 CLIP 가중치를 다시 받아 초기화할 필요가 없지만 missing key를 허용해서는 안 된다. 추가 training0.

Primary score는10개 sigmoid(cos-positive − cos-negative)의 산술평균이다. 확률 모양을 가지지만 NIH에 교정된 질환 확률이라고 부르지 않는다. 개인 checkpoint 성능은 primary 선택에 쓰지 않는다. 20환자×4군, target-vs-rest/opposite/normal/effusion AUC/AP, 군별 환자 bootstrap2,000회와95% percentile구간, threshold 미선택을 유지한다.

두 target 각각 vs-rest AUC≥0.70/95%하한>0.50, vs-opposite AUC≥0.60/95%하한>0.50을 모두 만족해야 개발 관문 통과다. 이 joint gate는 임상 certification·power 보장이 아니다. 어느 하나만 성공하면 공동 가설은 미통과이고 결과를 보고 한 질환을 삭제하지 않는다. 둘 다 통과해도 생성 artifact의 score 취약성 확인은 별도 필요하다.

5. 제한과 분기

이번에는 공식 source와10checkpoint를 확보/검사하고 데이터 예약 명세를 만들되 성능 validation을 실행했다고 쓰지 않는다. Checkpoint 다운로드/호환성이 실패하면 부분자산을 보존하고 정확한 부족분을 기록한다. 결과를 보려면 이후 source/weight/patient/전처리/runner/verifier를 한 실행 계약에 결속해야 한다.

다음 한 번의 CheXzero 검증에서 joint gate 실패 시 세 번째 classifier, 새prompt, 다른 checkpoint 조합으로 구제하지 않는다. 임상의 판독/전문 annotation/외부 조건 자료와 같은 측정 자원이 없으면 현재 폐기종·기흉 targeted 경로를 보류한다. 통과 시에도 generator/private head 성공이 아니며 고정 비DP 비교가 그 다음이다. 이 경계는 기존 작은 head/DP 결과와 별도로 보존한다.
