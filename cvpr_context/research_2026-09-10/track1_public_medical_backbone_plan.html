방향1: 공개 의료 기반모델의 자료·훈련·선택 기준

판정: 실행 준비는 이전보다 좋아졌다. 새 생성 성능을 얻은 결과는 아니다. 공개32명만 되풀이할 필요 없이, 기존 사적·평가 역할과 분리된 로컬 공개 자료로 의료 기반모델을 만들 수 있다. 640명·749장으로 fresh LoRA 한 번, 영상당4회·8회 노출의 두 checkpoint, 별도 생성 입력으로 선택 후 한 번 확인하는 계획을 고정했다. 이번 새 학습·생성·GPU 실행은0이다.

큰 단계2·방향1을 유지한다. 다음 실행이 답할 질문은 ‘보호 대상 환자를 학습하지 않은 공개 의료 출발점이, 현재 sampling 조건에서 작은 head를 시험할 만한 형태를 만드는가’다. 기존 M1의 사적 학습을 공개 학습으로 재분류하지 않으며, 아직 private head나 새 DP solver를 실행하지 않는다.

1. 사용자 검토에서 채택한 것과 바로잡은 것

  • 공개자료로 의료 domain을 먼저 형성하고, 사적 환자자료의 추가 적응만 작게 보호한다는 후보를 유지한다. 사전학습+사적적응이라는 구조 자체를 새 기여로 주장하지 않는다.
  • 기존1000step 복제 대신 영상당 노출과 총 optimizer update를 함께 고정한다. 동일 노출량은 동일 학습 난이도·품질·최적화 조건을 뜻하지 않는다.
  • 공개 선택과 확인 입력을 분리하고, 기존 두 진단 이미지를 독립 성능 증거로 다시 쓰지 않는다.
  • 무작위 projection P의 재생성은 필수가 아니다. 현재P는 공개 seed의 Gaussian QR로 만들어지고 데이터나 모델 출력을 읽지 않는다.320채널 feature tap과 정의가 같으면 P를 그대로 고정할 수 있다. 바뀐 UNet의 특징·기본 예측·잔차·A/B/Q·학습 W 및 witness는 반드시 다시 계산한다. 같은 VAE/text/preprocessing의 latent·embedding은 원칙적으로 재사용할 수 있으나, 이번 새749장은 기존 혼합역할 cache에 없으므로 새로 준비한다.
  • 기관이 다른 외부 자료가 있어야만 pilot이 가능한 것은 아니다. 이번은 NIH 안의 환자 역할 분할이며 외부 병원 일반화라고 표현하지 않는다.

2. 공개 범위와 실제 분할

NIH 데이터 제공 문서는 이용 제한 없음과 출처·원논문 인용 조건을 안내한다. 공식 제공 문서. 새 다운로드나 비용 발생 없이 기존 로컬 파일을 사용한다. CheXpert/MIMIC의 접근 조건과 모델 배포 출처는 별도 확인 메모에 남겼다.

기존 public_development1,816명에서 현재 fit80/dev40/cal140/test140/public32와 reference/background 역할 및 reference259를 환자 단위로 제외하면905명·1,016장이 남는다. 제외 대상의 합집합은911명이며 중복 수를 이중 차감하지 않았다. 원 명부의 partition을 바꾸지 않고 새 backbone_role 열로만 역할을 지정했다.

조사한 진단명부와 겹치지 않는 환자 중 확인128→선택128을 먼저 SHA 순서로 배정했다. 학습640명에는 기존 공개 geometry/gradient 등의 진단 이력이 있는117명이 들어간다. 선택·확인0명, 예비1명이다. ‘조사한 진단명부와 미중복’이지 완전한 미관측 외부 test라는 뜻은 아니다. 학습의 label 빈도는 No Finding424/Effusion71/Cardiomegaly23영상이며 NLP 약한 라벨이다.

자료1,016장 모두 실제 파일 SHA 확인과 명부 재구성 검증을 완료했다. 기존 pixel hash의 환자 간 exact 중복도 없었다. 새로운 유사영상 검색이나 임상 판독은 하지 않았다. 자료 감사, 환자 CSV, 영상 CSV.

첫 생성 관문의 평가 단위는 아래의 새 prompt·seed 입력이다. 예약128명씩을 실제 모델 평가에 사용한 것처럼 보고하지 않는다. 기존 public32는 작은 head의 공개전용 기준선을 위해 그대로 남긴다.

3. 고정한 학습량과 구현 경계

기존 M1은912장×평균4.386회, batch4·1000step이었다. 이번은749장이므로 한 fresh run의8개 순열을 연결해 총1,498회 성공 update까지 실행한다.

checkpoint 성공 update 귀속된 영상 노출 영상당 노출
E4 749 2,996 정확4회
E8 1,498 5,992 정확8회

이미지별 epoch 순서는 고정 salt·epoch·image_id의 SHA 순위로 정하고, epoch 경계를 넘어4개씩 배치로 묶는다. 기존 trainer의 N%4==0 가정은749장에서 성립하지 않으므로 옛 파일을 그대로 호출하지 않는다. 영상이나 환자를 버리거나 padding 복제해 수를 맞추지 않는다. 공개 비DP domain 학습은 이미지 균등이며 환자 균등은 아니다. 이후 보호 학습의 patient unit과 구분한다.

예정된5,992개 노출 순서와 step별 timestep/noise seed를 CSV로 저장하고 별도 구현에서 재계산했다. GradScaler가 update를 건너뛰면 실제 시도한 노출·forward/backward는 늘 수 있으므로 성공 update 귀속 노출과 실제 모든 시도를 따로 기록한다. 총100회 overflow 실패를 넘으면 중단하며 성공한 것처럼 exposure를 세지 않는다.

초기화는 기존 고정 SD2.1 snapshot 0094d483a120f3f33dafbd187ea4aa60d10de75c, fresh rank8/alpha8 LoRA, init seed260914다. M1/M2 weights나 optimizer는 읽지 않는다. AdamW lr1e-4,β(.9,.999),eps1e-8,weight decay.01,grad norm cap1,FP16 autocast·FP32 LoRA,초기 scaler1024를 유지한다. 기존 VAE latent mode·256px 전처리와 weak-label conditioning을 사용하고 VAE/text encoder는 동결한다. conditioning dropout이나 CFG 정책을 탐색하지 않는다.

이것은 자료·학습·평가의 사전 명세다. 새 runner와 public-only cache는 아직 구현·실행하지 않았다. 다음 패키지에서 새 파일로 구현하고, 자료경계·sampler·zero-adapter·sampling 정합을 필요한 범위로 확인한 뒤 코드 hash를 묶어 한 번 실행한다. 옛 frozen trainer/계약은 수정하지 않는다.

4. checkpoint 선택과 한 번의 확인

sampling은 현재와 같은256px·DDIM30·eta0·FP32·CFG1이다. 실제 초기 latent와 prompt embedding을 저장해 두 checkpoint에 똑같이 준다. 이미 본 normal/effusion 두 입력은 각 checkpoint의 연결 진단에만 사용하고 선택 점수에서 제외한다.

선택: generic/no-finding/effusion/cardiomegaly의4개 prompt×새 seed4개, checkpoint당16장이다. 두 checkpoint가 같은16입력을 공유한다. 조건 이름은 요청 문구이고 질환 정확성 판독이 아니다.

각 영상은 정면 흉부 방사선영상에 가까운 전체 구조가 있고 심한 회전·중첩·비의료적 패턴·큰 형상 붕괴가 없는지를 본다. checkpoint 표기를 숨기고 순서를 hash로 섞어 두 assistant가 확인한다. 애매하거나 의견이 갈리면 미통과로 기록한다. 이는 임상 전문가 판독이 아니다.

전체 12/16 이상, prompt별 2/4 이상을 만족하면 운영상 통과다. 이 임계값은 결과 전에 정한 pilot 투자 기준이며 임상/통계적으로 검증된 품질 기준이 아니다. E4가 통과하면 E4, 아니면 E8을 보며 가장 높은 점수를 낸 checkpoint를 고르지 않는다. 학습은 한 trajectory의 사전 고정8회까지만 수행한다.

확인: 선택한 checkpoint 하나에 별도의16개 새 seed 입력을 한 번만 적용하고 같은 기준으로 판단한다. 확인에서 실패하면 E8이나 다른 seed로 같은 확인 세트를 반복해서 구제하지 않는다. 선택·확인 모두 실패 결과를 포함해 전부 보존한다. 둘 다 선택 관문을 못 넘으면 확인을 실행하지 않는다.

최대 생성량은 선택32장+확인16장+옛 입력 진단4장=52장, sampling UNet 최대1,560forward다. 앞선 ‘96장 확대 보류’는 작은 head/DP 방법 비교를 보류한다는 뜻이며, 이번 공개 backbone 자체의 고정된 확인은 별도다. RAD-DINO/KID/BioViL 수치를 이 소표본의 성공 증거로 쓰지 않는다.

5. 통과 뒤에만 진행할 질문

선정한 공개 checkpoint를 고정하고 그 위에서 특징·A/B/Q 및 W0/public-only/pooled 비DP head를 새로 만든다. 공개전용보다 private80을 더한 head의 실제 생성 효용이 나아지는가가 다음 핵심 질문이다. 개선이 없다고 작은 표본만으로 영구 불가능을 단정하지 않지만, 개선 근거 없이 DP solver를 늘리지 않는다.

더 많은 공개 학습으로 private 추가 이득이 오히려 줄 수 있다. 이를 숨기기 위해 공개자료를 고의로 약하게 만들지 않는다. 충분한 공개 출발점에서도 사적 데이터가 유용한 변화와 품질–비용 절충을 제공하는지는 아직 미확인이다. 같은 공개 checkpoint·자료 예산을 strong patient-DP baseline에도 제공한다.

선정한 공개 domain adaptation은 protected-role 환자와 분리되지만, 원 foundation model의 전체 웹 사전학습 이력까지 감사한 것은 아니다. 향후 DP 주장은 고정된 기반모델과 공개 보조정보 아래 새 private adaptation의 인접성 범위로 명시한다. 이 공개 backbone 자체에 환자DP를 적용했다고 주장하지 않는다.

기존 동일 계열1000step의 실측496.731초를 단순 비례하면1,498step은744.103초,약12.4분이다. 이는 새 측정값이 아니다. 새 자료 IO·cache·재시도·장치 부하를 반영해 범위를 제시했다. 실제 실행에서 단계별 시간과 peak memory를 다시 기록한다. 모델 선택·공개 학습 비용은 모든 방법의 공통 준비비로 표시하고, 처음부터의 전체 비용과 반복 private adaptation의 비용을 따로 보고한다.

이번 작업은 자료·노출·평가 명세와 CPU 검산까지다. 의료 backbone 확보 성공이나 학습 완료를 보고하는 단계가 아니다.
