# 졸업논문·CVPR 공통 실험 재사용과 분기 계획

**후속 권장 구조(2026-09-10):** 새 감사법 설계를 구체화한 뒤 졸업논문의 중심·연구질문·목차와의 관계를 [26번 기록](26_CVPR추진시_졸업논문_중심과_공통실증_2026-09-10.md)에 정리했다. 아래의 18번 문헌 해석·미확정 후보는 당시 이력이며 최신 선행 판정과 실제 설계는 23–26번을 함께 따른다.

- 기록일: 2026-09-09
- 성격: 사용자의 병행 연구 의향과 공통 산출물 운영 원칙을 기록한 계획
- 선행연구·기여도 판정 기준: [18번 검토](<18_CVPR_SOTA_전수대조와_투고가능성_판정_2026-09-08.md>)
- 실행 상태 기준: [CURRENT_STATUS.md](../CURRENT_STATUS.md)

## 1. 사용자가 정한 방향

CVPR 선행연구를 조사하면서 연구질문과 기여도를 좁히고, 졸업논문에 필요한 전체 실증도 진행한다.
공통으로 쓸 수 있는 데이터·코드·실험 산출물은 함께 사용하고, 연구질문이나 조건이 달라지는 작업은
별도로 수행한다. 두 연구를 무조건 하나의 학습·평가 계약에 합치는 것을 목표로 삼지는 않는다.

졸업논문은 DP 학습/감사, 정확한 모델에 대한 receipt, PP-Mark와 통합 검증까지의 범위를 유지한다.
CVPR은 18번의 환자 집합 단위 공격·감사 후보를 출발점으로 삼되, 신규성이나 우월성이 검증된 것으로
간주하지 않는다. 이 파일은 새로운 통계량·공격법·비교군의 확정 문서가 아니다.

## 2. 공통으로 쓰는 것과 별도로 만드는 것

| 산출물 | 활용 방식 | 재사용 조건 또는 별도 작업 |
|---|---|---|
| 확보된 NIH 원본 | 공통 | 같은 source/hash를 참조하며 원본을 중복 복사하지 않는다. |
| 환자별 mapping·cap·split manifest | 조건부 공통 | 동일 모집단·환자 분할·cap일 때 재사용한다. 다른 데이터셋·분할은 별도 버전이다. |
| 전처리, SD 2.1, LoRA, DP trainer와 accountant | 공통 구현 기반 | 설정 변경은 새로운 설정/실행 ID로 관리한다. 기존 동결 결과를 덮어쓰지 않는다. |
| B0 448장 | 공통 기반 검증 | 동일 prompt/seed 출력의 무결성과 기본 모델 검토에 재사용한다. 새로운 공격 query 예산은 별도 생성이 필요하다. |
| M0·K5 feasibility | 공통 실행 가능성 근거 | 현재 K5는 단일 seed의 예비실험이다. CVPR 확증 결과나 신규 공격 개발 결과로 승격하지 않는다. |
| K10 학습 checkpoint | 조건부 공통 | 데이터, 모델, 학습 메커니즘, budget, seed와 최종 step이 일치하는 실험에서 같은 checkpoint를 참조한다. |
| 생성 품질·기본 privacy 평가 | 조건부 공통 | 동일 모델·생성 조건·평가 표본·지표 계약일 때 결과를 공유한다. 새 지표는 동일 모델에서 추가 평가할 수 있다. |
| CVPR 신규 공격·보정·추가 baseline | 별도 | 통계량, 위협모델, 개발/보정/평가 분할과 비교 조건을 별도로 정한다. 기존 checkpoint 활용 가능성을 먼저 확인한다. |
| CVPR 추가 dataset·backbone·privacy budget | 별도 | 실제로 달라진 학습 조건만 추가 학습한다. 자원 예산을 별도로 산정한다. |
| 모델 결속 receipt·PP-Mark·증거 교체 검증 | 졸업논문 중심 | 같은 모델의 신원과 원본 증거를 참조한다. CVPR 중심 기여에 넣을지는 연구질문에 따라 정한다. |
| 논문 집필 | 별도 | 공유된 실험의 ID와 근거는 같게 유지하고, 각 원고의 질문·주장·평가 범위에 맞춰 작성한다. |

공유 가능하다는 것은 결과를 미리 같은 표에 넣어도 된다는 뜻이 아니다. 동일 조건의 동일 산출물인지
확인한 다음 참조를 공유한다. 특히 원본 생성물과 PP-Mark 적용 생성물은 구분하여 비교한다.

## 3. 실제 병행 순서

| 졸업논문 실행 흐름 | 같은 기간의 CVPR 작업 | 합류할 지점 |
|---|---|---|
| M0 학습·생성·기존 domain gate 평가 | 18번 핵심 선행 원문 재검증, 이미 점유된 기여와 남은 질문 정리 | 의료 생성의 실행 가능성과 후보 기여 문장 |
| M0 통과 후 K5의 세 DP 조건 실행 | 공격·감사 후보의 정확한 정의, baseline·반증 조건·개발 계획 작성 | K10에서 공유할 조건과 별도 조건 대조표 |
| 동결된 K10 비교·반복 실행 | 새 감사법 구현, 순수/CPU 테스트, 별도 개발용 실험 | 동일 checkpoint에 적용할 수 있는 평가 도구 |
| 공격·효용 평가와 receipt·PP-Mark 통합 | 동결된 CVPR 평가 및 추가 dataset/backbone 실험 | 공유 결과표와 각 연구 고유 결과표 |
| 졸업논문 통합 장·결론·초록 작성 | CVPR 방법·기여·실험 원고 작성 | 주장별 근거 추적 |

현재 RTX 3070 한 대에서는 큰 GPU 작업을 한 번에 하나씩 배치한다. 장시간 학습 중에는 원문 조사,
설계, 코드 작성과 가벼운 CPU 테스트를 진행한다. 새 공격의 GPU 검증이나 작은 target-model 학습은
학습 세션 사이에 예약한다. 병행은 총 GPU 계산량을 없애는 방식이 아니라 대기 시간과 중복 실행을
줄이는 방식이다.

## 4. K10 시작 전에 확인할 재사용 조건

18번 CVPR안은 현재 졸업논문 계약보다 넓다. 특히 다음 차이를 먼저 대조해야 한다.

1. **중심 기여:** 새 공격·감사법이면 기존 target checkpoint를 평가 대상으로 공유하기 쉽다.
   학습 메커니즘 자체를 바꾸면 그 방법의 학습은 새로 필요하다.
2. **데이터:** 졸업논문 core는 NIH다. 18번의 CVPR 권장안은 MIMIC-CXR 중심에 NIH 복제를 제시한다.
   그 방향을 유지하면 NIH 결과는 한 데이터셋의 결과로 공유하고 MIMIC 실험은 추가한다.
3. **비교군과 학습 설정:** 18번은 Kaiser sampling/clipping adaptation과 DP-LoRA/noise
   multiplicity 대조를 요구한다. 이 때문에 학습 설정이 달라지면 기존 K10을 같은 조건의 결과로
   취급할 수 없다. 어떤 조건이 공통인지와 추가 학습 수를 먼저 적는다.
4. **예산·반복:** 졸업논문 기본 patient budget 한 점과 핵심 세 seed가 CVPR 전체 실험을
   대체하지는 않는다. 추가 epsilon이나 backbone이 실제 기여 검증에 필요한지 구체화한다.
5. **평가 대상과 보정:** 새 공격의 입력 접근 권한, patient 통계량, null calibration, low-FPR
   표본 수, split-bias control, 반복·신뢰구간을 최종 결과 확인 전에 정한다.

Kaiser 원문에는 CheXpert 분류 환경에서 sampling adaptation과 clipping adaptation을 제안하고
naive group conversion과 비교한 근거가 있다. 현재 diffusion 환경에 맞는 비교 구현과 회계는
별도로 검증해야 한다.
출처: [User-Level Differential Privacy in Medical Machine Learning](https://tpdp.journalprivacyconfidentiality.org/2025/pdf/kaiser.pdf).

CVPR 기여도가 아직 열려 있어도 기존 졸업논문 실험은 독립된 목적을 가진다. CVPR에 재사용할 수 없는
조건이 생기면 그 차이를 기록하고 별도 실험으로 분기한다. 관측된 성능 순위에 맞춰 기존 비교군을
삭제하거나 유리한 결과만 CVPR 근거로 고르지 않는다.

## 5. 개발 결과와 확증 결과의 경계

- 현재 K5 계약에는 membership/memorization/extraction 공격을 넣지 않는다. CVPR 신규 공격의
  개발은 별도 개발용 모델·환자 집합과 계약으로 설계한다. K5를 공격 개발용으로 바꾸려면 그 변경을
  먼저 문서화하고 이후 확증 결과와 분리한다.
- 최종 holdout을 보며 공격 점수·threshold·모델 선택을 조정하지 않는다. 이미 개발에 사용한
  모델/표본/결과는 그 용도를 기록하며 독립적인 최종 검증 근거로 다시 세지 않는다.
- 같은 모델·이미지·평가 결과를 두 연구에서 참조해도 독립 반복 두 건으로 세지 않는다.
- 현재 연구용 PRNG 실행의 RESEARCH_ONLY 경계는 재사용해도 유지한다. 정식 DP release를
  주장하려면 기존 계약이 요구하는 보안 난수 경로와 새 학습 근거가 필요하다.

## 6. 다음에 구체화할 산출물

1. CVPR 후보별로 가장 가까운 선행, 새로 추가할 정확한 주장, 이를 반증할 비교를 적은 짧은 표.
2. 각 K10 실행이 졸업논문 전용/공통/CVPR 추가 중 어디에 속하는지 나타낸 설정 대조표.
3. CVPR 개발·보정·최종평가 분할과 첫 소규모 검증 계약.

이번 단계에서 작성한 것은 병행 운영 계획이다. 새 학습, 신규 공격, 동결 프로토콜 변경 또는
실험 성능 검증을 수행한 기록은 아니다. 기존 B0·4-step dry-run과 full M0 미시작 상태를 유지한다.

## 7. 두 원고의 초점 — 후속 대화 반영

사용자는 졸업논문에서 연구의 타당성·동기·결과 차이·기대효과를 충분히 설명하고, CVPR에서는
선행연구 대비 기여를 더 좁히며 SOTA 비교를 강화하는 방향을 제안했다. 다음과 같이 구체화한다.

| 관점 | 졸업논문 | CVPR |
|---|---|---|
| 중심 질문 | DP 감사와 생성물 출처 증거를 왜 연결하며 어디까지 유효한가 | 가장 가까운 강한 선행이 놓치는 정확한 문제를 어떻게 해결하는가 |
| 중심 기여 | 학습·감사·모델 receipt·PP 검증의 연결과 보장 범위 | 좁고 독립적인 새 방법·분석·발견 |
| 실증 | 허용/차단 조건, 품질·유출 위험·비용, 증거 교체 방어와 한계 | 공정한 강한 baseline 비교, 구성요소별 분석, 불확실성·독립 복제 |
| 효과의 기술 | 기대효과와 실측 효과를 구분하여 전체 연구의 의미를 설명 | 핵심 개선의 크기, 작동 이유, 적용 범위와 실패 조건을 설명 |

두 원고 모두 독립적인 기여와 엄밀한 증거가 필요하다. 졸업논문을 동기 설명만으로 완성하거나
CVPR을 SOTA 숫자 경쟁만으로 정의하지 않는다. CVPR 2026 공식 심사지침은 기존 benchmark의
SOTA 정확도를 넘지 못했다는 사실만으로 기각하지 말고 신규성과 잠재적 영향을 함께 평가하도록
명시한다. 이는 확인한 2026 지침의 내용이며 2027 심사지침을 확인했다는 주장은 아니다.
출처: [CVPR 2026 Reviewer Guidelines](https://cvpr.thecvf.com/Conferences/2026/ReviewerGuidelines).

현재 CVPR 후보는 가변 환자 기록 수·영상 간 상관 때문에 발생할 수 있는 감사 점수의 왜곡을
검증하고, 환자 단위 오탐 보정과 위험 검출을 개선하는 방향이다. 이것은 아직 가설이다. 이 후보를
유지하면 주요 방법 비교는 공격·감사 baseline에 두고 DP 모델들은 그 감사법의 평가 대상으로
활용한다. 생성 품질 최고 기록을 달성하는 것을 자동으로 중심 기여로 삼지 않는다.

다음 기여도 검토는 가장 가까운 선행 3~5개별로 다음을 채우는 형태로 진행한다.

- 이미 해결한 문제와 그대로 재사용하는 구성요소
- 아직 해결하지 못했다고 판단하는 구체적 상황과 이를 뒷받침할 근거
- 새로 추가할 정확한 한 가지와 그것을 반증할 대조 실험
- 동일 위협모델·privacy budget·연산 조건에서 비교할 지표와 baseline

## 8. 대화에서 검토한 반복 수·시간 예산

### 실험 범위 선택과 각 비교의 역할

- K10 핵심 4조건 × 3 seeds = 12회는 현재 계약의 설계다. 이 전체 구성이 졸업논문의 보편적
  최소 요건이거나, 3 seeds의 통계적 충분성이 확인됐다는 뜻은 아니다.
- M0는 생성 품질과 비용의 기준, M1-I8은 image/patient 단위 불일치 사례,
  M1-G8과 M2-P8은 같은 환자 예산에서 group-converted image-DP와 직접 patient-DP를
  비교하는 핵심 조건이다.
- 등록된 회계에서 환자 claim이 차단되는지는 계산·감사 테스트로 검증할 수 있다.
  실제 생성 품질, 공격 성공률, 비용 차이를 얻으려면 학습·평가가 필요하다.
- M1-G8은 처음부터 더 강한 image-DP 설정으로 학습하는 별도 모델이다. 감사가 M1-I8의
  가중치나 프라이버시를 개선하는 것이 아니다. 재사용 비용은 기존 학습비와 추가 감사비를
  구분하여 계산한다.
- 반복 학습은 학습 무작위성의 변동을 본다. 환자 bootstrap은 하나의 학습 모델을 조건으로
  하는 평가 표본 변동을 다루며, 반복 학습의 변동을 대신하지 않는다.
- 범위를 축소할 수 있는 경우와 잃게 되는 주장을 설명한 뒤, 사용자는 전체 실증 범위를
  유지하는 의향을 밝혔다. 원하는 성능 순위가 나올 것을 전제로 한 선택은 아니다.

### 시간 수치의 근거와 한계

아래는 이번 대화의 일정 설명을 보존한 것이다. RTX 3070 한 대를 거의 전용으로 사용한다는
가정이며, 확정 실행시간이나 CVPR 전체 연구비용으로 해석하지 않는다.

| 항목 | 대화에서 제시한 범위 | 근거/분류 |
|---|---|---|
| K5 M0 학습 | 1~3시간 | 장시간 실행 전 추정 |
| K5 M1-I8 학습 | 5~6시간 | 4-step 실측 17.562초를 4,000 steps로 선형 환산하면 루프 약 4.878시간 |
| K5 M1-G8 학습 | 5~6시간 | 4-step 실측 17.411초의 같은 환산은 약 4.836시간 |
| K5 M2-P8 학습 | 2~3시간 | 4-step 실측 7.945초의 같은 환산은 약 2.207시간 |
| K5 전체 | 16~21시간, 점검 포함 약 1~2일 | 기존 실행계획의 학습·저장·생성·평가·여유시간 합계 |
| K10 핵심 12회 학습 | 약 39~48시간 | K5 속도와 M0 추정치를 이용한 계산, K10 실측 없음 |
| K10 추가 대조군·생성·점검 포함 | 약 50~80시간 실행 예산 | 추가 설정·구현에 따라 달라지는 넓은 추정 |
| K10 준비·점검 포함 일정 | 약 4~7일 | 50~80시간을 4~7일의 연속 GPU 시간으로 해석하지 않는다. 연속 가동 환산은 약 2~3.3일이다. |
| 공격·생성 품질·활용 효용 평가 | 5~10작업일 | 미구현 작업과 분석을 포함한 추정 |
| DP 감사 연결·model receipt | 3~5작업일 | 미구현 작업의 추정 |
| 의료모델 PP-Mark 통합 | 3~7작업일 | 재보정·통합·공격 검증의 추정 |
| 전체 통합 검증 | 3~5작업일 | 증거 교체·재사용 공격·비용 측정의 추정 |
| 본문 개편·표·그림·조판 | 5~10작업일 | 결과 동결 후 집필·QA 추정 |
| 남은 졸업논문 통합 실증·본문 반영 | 약 5~9주 | 집중 작업과 일부 병행을 가정한 보조 일정, 완수 시점 보장 없음 |

K5의 시간 근거는 기존 실행계획과 dry-run report다. K10 및 미구현 단계의 수치는 대화 중
산정한 추정이며 아직 측정값이 아니다. 초기 전체 연구 마일스톤과는 시작점·남은 범위가 다르다.
M0 domain adaptation이나 PP-Mark 재보정에 재설계가 필요하면 기간이 늘어난다. CVPR의 새 방법,
추가 dataset·backbone·target models 및 정식 DP release용 보안 난수 경로/재학습은 별도 산정한다.

## 9. 지속 기록 방식

사용자는 모든 작업에서 기록을 함께 남기도록 요청했다. 대화의 연구 결정·근거·수치·변경 사유·
남은 일을 문서화하며, 다음 단계에서는 이전 기록을 먼저 읽고 이어서 작업한다.

- 실제 실행 상태와 기록 해석은 CURRENT_STATUS.md, 작업 경과와 변경 이유는 WORKLOG.md에 남긴다.
- 선행·기여도 검토는 CVPR 주제 탐색 폴더에 보존한다. 18번은 기존 기여도 판정, 19번은 공통
  운영·원고 초점·시간 추정 기록이다.
- 사용자 방향, 제안/가설, 동결된 계약, 실제 실행, 검증된 결과를 구분한다.
- 문헌 주장에는 원문 근거와 확인 범위를, 수치에는 측정/계산/추정 여부를, 실험에는 설정과
  결과 artifact 위치를 남긴다.
- 반증·실패·폐기 이유와 과거 판단을 보존하고, 수정할 때는 무엇이 후속 판단으로 바뀌었는지 적는다.
- 이 기록 요청은 대화·계획 정리를 학습 실행으로 취급하지 않는다. 이번 대화에서는 M0 본 학습이나
  CVPR 신규 공격을 실행하지 않았다.
